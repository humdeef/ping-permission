# user-app: Consumer User Domain

`user-app` is responsible for **mobile / consumer users**: it uses a separate `app_user` table and a separate App login domain (`StpAppUtil`), fully isolated from the backend `sys_user`. It does not handle PC pages or participate in backend RBAC permissions.

## 1. What It Contains

| Class | Purpose |
| --- | --- |
| `controller.AppAuthController` | `/user/app/auth/**` registration, login, logout, current user |
| `service.AppAuthService` / `impl.AppAuthServiceImpl` | Phone registration/login, password validation, status validation |
| `service.dubbo.AppUserDubboServiceImpl` | Implements `AppUserDubboClient`, for other services to query nicknames |
| `entity.AppUser` | `app_user` table |
| `entity.AppUserIdentity` | `app_user_identity` table (phone/WeChat/Apple and other identities) |
| `mapper.AppUserMapper` / `AppUserIdentityMapper` | MyBatis-Plus Mappers |
| `model.*` | Registration/login/response DTOs |

Dependencies:

```
user-app
 ├─ user-common
 ├─ user-auth            Password policy
 ├─ user-client          AppUserDubboClient contract
 ├─ ping-web-spring-boot-starter
 ├─ mybatis-plus
 └─ dubbo
```

## 2. Data Model

### 2.1 `app_user`

| Field | Description |
| --- | --- |
| `id` | **Snowflake ID, generated at the application layer** (`IdType.INPUT`), not auto-increment |
| `phone` | Phone number, unique |
| `password_hash` | BCrypt hash, `@JsonIgnore`, not serialized |
| `nickname` | Nickname; defaults to the phone number at registration when empty |
| `avatar` / `gender` | Profile |
| `status` | 0 disabled / 1 normal / 2 deactivating |
| `register_source` | Registration source, currently `phone` |
| `last_login_at` | Last login time |
| `create_time` / `update_time` | Auto-fill |

### 2.2 `app_user_identity`

Reserved for future multi-identity login:

```
provider    = phone / wechat / apple / alipay
identifier  = phone number / OpenID / UnionID
credential  = third-party credential
```

Currently, registration also writes a record with `provider = phone` and an empty `credential` string.

> The IDs of both `app_user` and `app_user_identity` are generated by `DistributedIdGenerator`. They have no relationship with the auto-increment value of `sys_user.id`, and cross-use is forbidden.

## 3. Endpoints

| Method | Path | Policy | Description |
| --- | --- | --- | --- |
| POST | `/user/app/auth/register` | `@PublicApi` | Phone registration |
| POST | `/user/app/auth/login` | `@PublicApi` | Phone + password login |
| POST | `/user/app/auth/logout` | `@AppLoginOnlyApi` | Logout |
| GET | `/user/app/auth/me` | `@AppLoginOnlyApi` | Current App user |

### 3.1 Registration

```bash
curl -s -X POST http://localhost:9999/user/app/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13800000001","password":"Abc12345!","nickname":"Little P"}'
```

Flow:

1. `PasswordPolicy.validate(password)`;
2. Check whether the phone number is already registered;
3. Generate a snowflake ID and write to `app_user`;
4. Write to `app_user_identity(provider=phone)`;
5. Return user information (without the password hash).

### 3.2 Login

```bash
curl -s -X POST http://localhost:9999/user/app/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13800000001","password":"Abc12345!"}'
```

Flow:

1. Query `app_user` by phone number;
2. Verify the password with BCrypt;
3. Validate status (0 disabled / 2 deactivating → 403);
4. Update `last_login_at`;
5. `StpAppUtil.login(userId)`;
6. Write `APP_PHONE` to the token session;
7. Return the token, expiration time and user information.

Subsequent requests:

```bash
curl -s http://localhost:9999/user/app/auth/me \
  -H 'ping-token: Bearer <app-token>'
```

## 4. Login Domain Isolation

`StpAppUtil` is defined in `ping-core`:

```java
public final class StpAppUtil {
    public static final String TYPE = "app";
    public static final StpLogic LOGIC = new StpLogic(TYPE);
    // login / isLogin / checkLogin / getLoginId / ...
}
```

Isolation behavior:

| Scenario | Result |
| --- | --- |
| App token calls `/user/app/**` | Pass |
| App token calls `/user/pc/**` | 401 (the PC domain has no such login state) |
| PC token calls `/user/app/**` | 401 (the App domain has no such login state) |
| PC token calls `/order/app/**` (`@AppLoginOnlyApi`) | 401 |
| App token calls `/order/app/**` | Pass, with the `app` role in `UserContextHolder` |

**The login domain is determined by annotations, not by the URL prefix.** When the gateway sees `@AppLoginOnlyApi`, it calls `StpAppUtil.checkLogin()`; when it sees `@LoginOnlyApi` or no annotation, it uses `StpUtil`.

## 5. External Dubbo: `AppUserDubboClient`

```java
public interface AppUserDubboClient {
    String getNicknameById(Long userId);
}
```

Implementation:

```java
@DubboService
@RequiredArgsConstructor
public class AppUserDubboServiceImpl implements AppUserDubboClient {
    private final AppAuthService appAuthService;

    @Override
    public String getNicknameById(Long userId) {
        AppUser user = appAuthService.findById(userId);
        if (user == null) return null;
        return user.getNickname() == null || user.getNickname().isBlank()
                ? user.getPhone()
                : user.getNickname();
    }
}
```

Caller (for example, the App endpoints of order-service):

```java
@DubboReference(check = false, timeout = 3000)
private AppUserDubboClient appUserDubboClient;

String name = appUserDubboClient.getNicknameById(UserContextHolder.getUserId());
```

Why not use `UserDubboClient`? It queries `sys_user`; passing an App user ID would mix identities.

## 6. Pitfalls

### 6.1 Using `StpUtil` in App Endpoints

```java
// Wrong
@AppLoginOnlyApi
@GetMapping("/me")
public ApiResponse<?> me() {
    return ApiResponse.ok(StpUtil.getLoginId()); // Cannot get the App login state
}
```

App endpoints should consistently use `StpAppUtil`, or use `UserContextHolder.getUserId()` (the filter has already written it by domain).

### 6.2 Assuming App Registration Is Controlled by `ping.security.registration-enabled`

Currently `AppAuthController.register` does not read this switch, so App registration is always available. To disable it, add the check yourself:

```java
@PublicApi
@PostMapping("/register")
public ApiResponse<AppUserResponse> register(@RequestBody @Valid AppRegisterRequest req) {
    if (!securityProperties.isRegistrationEnabled()) {
        throw new AccessDeniedException("Registration is not enabled for this system");
    }
    ...
}
```

### 6.3 App Login Has No Failure Lockout or CAPTCHA

`AppAuthServiceImpl` only validates password/status and does not integrate `LoginAttemptService` or `CaptchaService`. If you need credential-stuffing protection, see the integration example in `user-auth/README.en.md`.

### 6.4 Phone Uniqueness Is Only Checked at the Application Layer

Registration does `selectCount` before `insert`, so duplicates are still possible under concurrency. The database should have a unique index; without one, concurrent registrations can write duplicate phone numbers. `GlobalExceptionHandler` converts `DuplicateKeyException` to 400, but only if the table has a unique constraint.

### 6.5 `passwordHash` Is Serialized

`AppUser.passwordHash` is annotated with `@JsonIgnore`, but if your new endpoint returns `AppUser` directly, it is still recommended to use `AppUserResponse` instead of relying on the annotation as a fallback.

### 6.6 Returning Long IDs to the Frontend

App user IDs are snowflake IDs (19 digits), beyond JavaScript's safe integer range (2^53-1). `AppLoginResponse.userId` and `AppUserResponse.userId` use `String`, avoiding precision loss. Keep this convention when adding DTOs.

### 6.7 App Endpoint Gets Gateway 403 "No permission rule configured for endpoint"

Check:

1. Whether the Controller or method has `@AppLoginOnlyApi` / `@PublicApi`;
2. Whether annotation scanning wrote to Redis: `ping:gateway:api:app-login:user-service`;
3. Whether you waited for the gateway's 10-second refresh cycle;
4. Whether the request really goes through the gateway (9999), not directly to 8099.

App endpoints do not need to register permission codes in `sys_api_resource` — annotations take effect before permission rules.

## 7. Add an App Endpoint

```java
@RestController
@RequestMapping("/user/app/profile")
@AppLoginOnlyApi
@RequiredArgsConstructor
public class AppProfileController {

    @GetMapping("/me")
    public ApiResponse<AppUserResponse> me() {
        Long userId = Long.valueOf(String.valueOf(StpAppUtil.getLoginId()));
        AppUser user = appAuthService.findById(userId);
        ...
    }
}
```

Checklist:

- [ ] Use the `/user/app/**` prefix (helpful for routing and troubleshooting, but not an authorization basis);
- [ ] Add `@AppLoginOnlyApi` to the class or method (use `@PublicApi` for public endpoints);
- [ ] Use `StpAppUtil` or `UserContextHolder` to get the current user;
- [ ] Use `AppUserDubboClient` when querying App users across services;
- [ ] Use String for Long IDs in returned DTOs;
- [ ] No need to change gateway configuration or `sys_api_resource`.

## 8. Dependency Usage

```xml
<dependency>
    <groupId>com.ping.user</groupId>
    <artifactId>user-app</artifactId>
</dependency>
```

Usually only `user-service` depends on it directly. When other services need App user capabilities, they depend on `user-client` and call `AppUserDubboClient`.
